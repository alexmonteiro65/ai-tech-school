How Claude Code actually works

Three diagrams: the core request loop, getting it installed, and how MCP extends what it can do.

The Claude Code loop

Every interaction follows the same cycle — and you stay in control at the approval step.

You make a request

In plain language, in your terminal.

Claude reads your files

It looks at the actual project, not a description of it.

Claude proposes a plan

Specific edits or commands, laid out before anything happens.

You review and approve

Nothing runs on your project without your say-so at this step.

Claude acts and reports back

Edits files, runs commands, or uses a tool — then shows the result.

This repeats for each new request — the loop is the whole model.

Getting it installed

How MCP extends it

MCP connects Claude Code to real tools and data through a consistent interface.

Claude Code (the Client)

Wants to do something outside the conversation — like check a repo.

An MCP Server

A connector exposing specific Tools, e.g. "create a pull request."

The real tool or data

GitHub, a database, Google Drive — whatever the server connects to.
