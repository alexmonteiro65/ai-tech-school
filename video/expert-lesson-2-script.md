## English

Hi, I'm AITS, your AI Tech School guide — here's the detailed walkthrough for this lesson. One agent, many tools — that's what this lesson is about.

Composio is a platform that provides ready-made MCP connectors for dozens of popular tools — Slack, Gmail, Notion, Google Calendar, GitHub, Linear, and more — so you don't build a custom connector for every service you want an agent to use. Instead of one agent hard-wired to one tool, Composio lets a single agent reach many tools through the same MCP interface, and the agent picks the right tool for each part of a task.

Here's what that looks like end to end: a new customer onboarding workflow, four tools, one agent. Gmail sends the welcome email. Notion creates the onboarding document. Slack notifies the team. Google Calendar schedules the kickoff call. One agent, coordinating all four.

But there's a real design principle to hold onto here: more connected tools means more capability, but also more surface area for mistakes. Only connect what the workflow actually needs — every extra connection is one more way things could go wrong, not just one more thing the agent can do.

On the page, you'll match a set of real tasks to the tool best suited to handle each one, then check your understanding with three quick questions. See you in Lesson 3, the final one: deploying a fully automated pipeline.

Before you try the quiz below, here's a quick preview of the three questions and their answers. Question 1: What problem does Composio solve? Is it It replaces Claude entirely, It provides ready-made MCP connectors so you don't build one per tool, It's a code editor, or It only works with one tool? The answer is It provides ready-made MCP connectors so you don't build one per tool — Composio's value is a library of existing connectors, so you're not building a custom integration for every service. Question 2: In a multi-tool workflow, how does the agent decide which tool to use? Is it It always uses every tool at once, It picks the right tool for each part of the task, Tools are chosen at random, or A human manually switches tools each time? The answer is It picks the right tool for each part of the task — Each part of a workflow maps to whichever connected tool actually handles that kind of action. Question 3: What's the tradeoff of connecting more tools to an agent? Is it There is no tradeoff, More capability, but more surface area for mistakes, It disables MCP, or It makes the agent unable to think? The answer is More capability, but more surface area for mistakes — Every additional tool is another way the agent could take an unintended action — connect only what the workflow needs.
